# Agent guide for vela

vela adds folder and file permissions (view, read, write) to self-hosted GitLab CE. This file is for AI coding agents (and humans) working **on this repository**. If you were asked to **install vela or set permissions on a GitLab server**, read [`docs/agent-guide.md`](./docs/agent-guide.md) instead. Both guides apply if you do both.

Claude Code, Codex, Cursor, Copilot, Gemini and others read this file. `CLAUDE.md` and `GEMINI.md` only point here.

## Commands

```bash
bin/test                      # all unit tests, plain minitest, Ruby 3.3+, no gems
ruby test/evaluator_test.rb   # one file
dev/up.sh                     # throwaway GitLab CE 19.0.2 in Docker (needs Docker or Colima)
dev/e2e.sh                    # live end-to-end suite against that container, rewrites docs/e2e-results.md
```

`bin/test` must pass before every commit. Run `dev/e2e.sh` for any change to `lib/path_permissions/write_check.rb`, `store.rb`, `install.rb` or `db/schema.sql`. Unit tests use a stand-in for GitLab, so they cannot prove behaviour on the real thing.

## Layout

```
lib/path_permissions/
  evaluator.rb     pure rules engine. No GitLab, no Rails, no I/O.
  write_check.rb   prepended onto Gitlab::Checks::DiffCheck; rejects forbidden pushes
  store.rb         loads rules and group ids from the add-on's tables
  install.rb       boot guard; raises if GitLab dropped the hook we rely on
overlay/           the one initializer copied into GitLab
db/schema.sql      add-on tables and grants
dev/               local GitLab container and the e2e suite
docs/              install guide, design, version audit, e2e results, agent guide
```

## Rules that must not be broken

1. **Fail closed.** If rules cannot be read, the actor is unknown, a listing is empty when it should not be, or anything raises, the answer is *deny*. Never add a `rescue` that returns "allowed".
2. **Never leak a hidden path name.** A denial message may name a path only if the actor can *view* it. Test it (see `test_forbidden_path_rejected_and_hidden_name_not_leaked`).
3. **`evaluator.rb` stays pure.** No `Rails`, no `Gitlab`, no database. It is the part that must be trivially reviewable.
4. **No runtime dependencies.** Plain Ruby in `lib/`. An access-control add-on should be readable in one sitting.
5. **vela only removes access.** It runs *in addition to* GitLab's own checks. Never use it to grant anything.
6. **Admins and project Owners are never locked out.**
7. **Do not guess GitLab internals.** Read the source at the target tag (clone `gitlab-foss` at that tag into a scratch directory), cite the file and line in `docs/version-audit.md`, and mark anything you could not run as UNVERIFIED. The e2e suite found three real bypasses that reading alone missed.
8. **Every access check change needs a test that fails first**, in `test/`, and for write-path changes a case in `dev/e2e.sh`.

## Semantics (see `evaluator.rb`)

- Levels: view, read, write. Each needs the ones before it. **A write rule alone grants nothing.**
- A directory rule covers its descendants. The most specific path wins. Deny beats allow at the same path.
- A path with any allow rule is an allow-list for every level. No rule means GitLab's native permissions decide.
- Paths: no leading slash, no trailing slash, no empty, `.` or `..` segments. Case-sensitive.

## Working in this repo

- **Never push to `main`.** It is protected by a ruleset. Branch (`feat/...`, `fix/...`, `docs/...`), commit with [Conventional Commits](https://www.conventionalcommits.org/), and open a pull request. PRs are squash-merged.
- Required checks: `test (Ruby 3.3)`, `test (Ruby 3.4)`, `Semgrep SAST`, `Gitleaks secret scan`. Keep them green.
- Pin new GitHub Actions to a full commit SHA, never a tag.
- Never commit secrets, tokens, `.env` files or `dev/.root_password`. Never print a token in logs or PR text.
- **Never touch a production GitLab** to test. Use `dev/up.sh`. The dev instance has no mirrors, webhooks or email by design.
- Tests and e2e scripts keep temporary files outside the repo.
- Update docs in the same PR as the behaviour: `README.md`, `docs/install.md`, and `docs/e2e-results.md` (regenerated by `dev/e2e.sh`, not edited by hand).
- Write docs in plain, human language. No filler, **no em dashes or en dashes**. Keep claims honest: say "tested on" only for what `dev/e2e.sh` ran.
- Report test results faithfully. If something failed or was skipped, say so.

## Known limits (do not paper over them in docs)

- `git clone` and `git fetch` are not restricted. View and Read rules do not hide content from anyone who can fetch.
- Only GitLab CE 19.0.x is tested.
- View and Read hiding is built for file lists, content, raw, blame, search, diffs, API and GraphQL. Commit history, archives, `repository/blobs/:sha`, export and compare are not filtered.
- Pushes to refs that are neither branches nor tags are not checked.
- GitLab's own `find_changed_paths` swallows Gitaly errors and returns `[]`. The branch net-diff check treats an empty answer for differing trees as unverifiable. The per-commit check cannot.

## Security issues
